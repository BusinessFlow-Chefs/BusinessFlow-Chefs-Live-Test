# BusinessFlow Chefs — Chef Mode Operating Rules

Status: APPROVED PRODUCT DIRECTION

## S.A.G.E.
- S.A.G.E. expansion: **Service AI-Powered Galley Expert**.
- Keep the S.A.G.E. orb gold.
- Keep the sound-wave treatment consistent with the Home screen; waves should be smaller and not oversized.

## Active alerts
- Active alerts remain visible on Home and relevant Menu workflow pages.
- Alerts should be visually brighter than passive information so time-critical actions stand out immediately.
- Alerts should focus on real operational timing: prep, service, inventory/provisioning checks and other current chef actions.
- Tapping an Active Alert should deep-link directly into **Chef Mode** at the exact task represented by that alert, not just open a generic Chef Mode landing state.

## Chef Mode as the working-day cockpit
- During an active charter day, Chef Mode is the chef's primary operational page and should be suitable to remain open for most of the day.
- Home is the overview; Charter and Menu are planning/review; Chef Mode is execution.
- Chef Mode should always show the current task, countdown/time remaining, next actions and the relevant recipe/instructions.
- If the active task is inventory or provisioning related, Chef Mode should still open to that task and provide a direct route into the detailed Inventory/Smart Provisioning screen only when deeper action is required.
- When no task is currently active, Chef Mode should show the next scheduled action and its countdown rather than becoming an empty screen.

## Continuity
- The same active task/countdown state must remain consistent across Home, Menu pages and Chef Mode.
- Completing, delaying or changing a task in Chef Mode must update the corresponding alert/countdown everywhere else.
